# نقشه راه توسعه و تثبیت سامانه HSCrm

این سند برنامه اجرایی ۵ فازی تاییدشده برای تثبیت فرم‌ها و توسعه امکانات جدید سامانه **HSCrm** (در دو مخزن `HSCrm.WebApi` و `HSCrm.Dashboard`) است.

---

## قوانین ثابت دامنه و معماری

1. **جدایی فاکتور خرید از مشتری و پروژه (قانون قطعی):**
   - در **فاکتور خرید (`PurchaseInvoice`)** هرگز `CustomerId` یا `ProjectId` ثبت نمی‌شود.
   - تجهیزات ابتدا از تامین‌کننده خریداری شده و وارد موجودی انبار (`Warehouse`) می‌شوند، و در زمان مصرف در پروژه از طریق **فاکتور فروش (`SalesInvoice`)** برای پروژه و مشتری ثبت می‌شوند.
2. **امنیت چندمستأجری و سال مالی:**
   - تمام درخواست‌های API باید توکن معتبر دارای `TenantId` و `FiscalYearId` داشته باشند و ایزوله‌سازی مستأجر (`TenantId`) در سطح پایگاه داده و کنترلر حفظ شود.
3. **سازگاری با تست‌ها و شاخه استقرار:**
   - هر تغییر در Entity / DTO / Controller همراه با تست‌های واحد در `HSCrm.UnitTests` و `HSCrm.Dashboard.UnitTests` ارائه می‌شود.

## فاز ۱ — زیرساخت، رفع باگ‌های کلیه فرم‌ها، تنظیمات شرکت و راه‌اندازی اولیه (اولویت فوری)

### ۱.۱. ممیزی و رفع باگ تمام فرم‌ها و ارتباطات داشبورد با WebApi
- [x] **فرم کاربران (`User/Index.cshtml` و `UserController`)**: اصلاح شناسه‌های اشتباه در مودال افزودن و ویرایش (`#UserFirstNameC`، `#UserLastNameC`، `#UserNameC`، `#PhoneNumberC`)، افزودن فیلد رمز عبور در مودال ایجاد و هم‌ترازی با `UserCreateModel`، اصلاح `for` برچسب آپلود تصویر، حذف شناسه‌های تکراری، اصلاح مجوزهای `Permissions.Users`.
- [x] **فرم مشتریان (`Customer/Index.cshtml` و `CustomerController`)**: اصلاح اعتبارسنجی `#btnCustomerSubmit` (جایگزینی `#Name` ناموجود با فیلدهای واقعی فرم)، اصلاح فیلدهای مودال ویرایش (`#TenantIdU`، `#ModifiedByIdU`) و حذف شناسه‌های تکراری.
- [x] **فرم کالاها و قیمت‌گذاری (`Product/Index.cshtml` و `ProductPrice/Index.cshtml`)**: اصلاح شناسه اشتباه `#ProId` در فرم قیمت‌گذاری، اصلاح `#EffectiveFrom` به جای `#ActionDate`، اصلاح حروف کوچک/بزرگ `#ProductTitle`، اصلاح `#chkActive` به `#IsActive`، نقل‌قول صحیح رشته‌ها در `onclick`، حذف شناسه‌های تکراری و بررسی حذف قیمت.
- [x] **فرم پروژه‌ها (`Project/Index.cshtml`)**: اصلاح بستن مودال ویرایش (`#editProject`) و محافظت در برابر `Customer` تهی (`CustomerId` اختیاری).
- [x] **فرم هزینه‌ها (`Expense/Index.cshtml`)**: هماهنگ‌سازی فیلدهای مودال ویرایش و محاسبه مانده با مدل واقعی، محافظت در برابر `Project` یا `CreatedBy` تهی و حذف شناسه‌های تکراری.
- [x] **فرم پرداخت‌ها (`Payment/Index.cshtml`)**: تعریف صحیح آدرس API (`@apiAddress` به جای `window.apiRoot`)، اصلاح انتخاب حساب بانکی و تاریخ، و اصلاح مجوزها از `Permissions.Products.*` به `Permissions.Payments.*`.
- [x] **ممیزی کامل سایر بخش‌ها (`Supplier`, `Warehouse`, `BankAccount`, `Cheque`, `FiscalYear`, `Receipt`, `Role`, `Invoice`, `ReturnInvoice`, `Accounting`)**: رفع تمام شناسه‌های تکراری، عدم تطابق فیلدهای JS/DTO و خطاهای رندر Razor.

### ۱.۲. تنظیمات جامع شرکت (`Company Settings`)
- [x] گسترش `Tenant` با فیلدهای:
  - `InvoiceNumberingMode` (`Auto` | `Manual` | `Hybrid`)
  - `DefaultVatPercent` (درصد ارزش افزوده پیش‌فرض)
  - `InvoiceFooterText` (متن پاورقی چاپ فاکتورها)
  - `DefaultCostingMethod` (روش پیش‌فرض قیمت‌گذاری موجودی: میانگین موزون / FIFO)
  - `DocumentLockDate` (تاریخ قفل اسناد حسابداری/انبار)
- [x] تکمیل کنترلر `TenantController` با:
  - `GetCompanySettings` و `UpdateCompanySettings` (شامل عنوان شرکت، تلفن، ایمیل، آدرس، شناسه اقتصادی/ملی `TaxId`، واحد پول، لوگو، روش شماره‌گذاری و الگوها، درصد VAT، پاورقی فاکتور، روش ارزش‌گذاری انبار و تاریخ قفل اسناد)
  - `UploadCompanyLogo` برای آپلود لوگوی شرکت
- [x] اتصال حالت شماره‌گذاری (`Auto` / `Manual` / `Hybrid`) به کنترلرها و فرم‌های ثبت فاکتور فروش، خرید و برگشتی‌ها.
- [x] ایجاد صفحه **«تنظیمات شرکت»** در داشبورد (`AdminArea/Settings/Index.cshtml`) با پیش‌نمایش زنده الگوی شماره‌گذاری فاکتور و افزودن آن به منوی کناری.

### ۱.۳. راهنمای راه‌اندازی اولیه شرکت (`Company Onboarding Checklist`)
- [x] پیاده‌سازی Endpoint وضعیت راه‌اندازی اولیه (`Tenant/GetOnboardingStatus`) برای بررسی موارد ضروری هر شرکت:

  2. تعریف حداقل یک حساب بانکی/صندوق
  3. تعریف حداقل یک انبار فعال
  4. تعریف حداقل یک کالا/خدمت
  5. تعریف حداقل یک مشتری
  6. تعریف حداقل یک تامین‌کننده
- [x] نمایش پنل/کارت راهنمای راه‌اندازی اولیه در داشبورد ادمین تا زمان تکمیل مراحل ضروری با لینک مستقیم به هر بخش و امکان بستن موقت اعلان.

### ۱.۴. تست‌های واحد فاز ۱

- [ ] ایجاد موجودیت `ProjectMember` (ارتباط چندبه‌چند بین `Project` و `ApplicationUser` با نقش در پروژه و نرخ ساعتی اختیاری).
- [ ] مدیریت اعضای پروژه توسط مدیر در جزئیات/مدیریت پروژه (تخصیص کاربر ۱، ۲، ۳ به پروژه ۱ و ...).
- [ ] ایجاد موجودیت `ProjectWorkLog` (ثبت ساعت کار روزانه با توضیحات، وضعیت تایید `Pending`/`Approved`/`Rejected`، تاییدکننده و محاسبه هزینه دستمزد).
- [ ] پیاده‌سازی پنل اختصاصی کارمندان / فیلتر دسترسی پروژه‌محور:
  - کارمند فقط پروژه‌هایی را می‌بیند که عضو آن‌هاست.
